# ADR-001 — Use Hangfire for recurring background work

## Status

Accepted

## Context

The service needs a recurring task that checks for jobs that have been open for more than seven days.

A timer inside the API would make the scheduling logic less visible and harder to monitor.

## Decision

Use Hangfire to register and monitor the recurring task.

The task is registered with:

`RecurringJob.AddOrUpdate`

and scheduled with:

`Cron.Daily`

## Consequences

### Positive

- Scheduling is explicit.
- A dashboard provides visibility into background jobs.
- The recurring task is separated from HTTP request handling.
- The implementation can later move to persistent Hangfire storage.

### Negative

- The service has an additional dependency.
- Production deployments should use persistent Hangfire storage instead of memory storage.
